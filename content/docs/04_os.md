## Basics

### What an OS does
- **Extended machine**: the OS hides hardware complexity behind simpler abstractions such as **system calls**. It is also the **resource manager**.
- **Time multiplexing** = take turns (CPU). **Space multiplexing** = each gets a part (memory).
- **Kernel (supervisor) mode** = OS runs with full hardware access; user mode = apps. A **system call** is how a program requests a kernel service.
- **Shell** = command interpreter, **not** part of the kernel.

### History and people
- **2nd generation** (transistors): **batch systems**, punched cards. **3rd generation** (ICs): **multiprogramming, spooling, timesharing**.
- **UNIX** descended from **MULTICS**. **Linux** was created by **Linus Torvalds**. **MINIX** (1987) by **Andrew Tanenbaum**. **CP/M** by **Gary Kildall**.
- **Ubuntu** = Linux distribution. **Android** = Google's mobile OS built on the **Linux kernel**.

### Types and structures
- **Hard real-time OS** must meet strict deadlines (pacemakers, airbags). Example RTOS: **VxWorks**.
- **Monolithic**: all procedures in one big program; any can call any other.
- **Microkernel**: minimal kernel; most services run as user-mode servers.
- **Virtual machine** structure: **IBM VM/370**. **Type 1 hypervisor** runs directly on **bare hardware**.

### Processes and threads
- **Process** = a program in execution. **PCB** (Process Control Block) holds PID, registers, state.
- **fork()** creates a new process; **exec()** replaces a process's program.
- **Zombie** = terminated, but parent has not collected its exit status.
- States: **Running → Ready** when the time slice expires; **Running → Blocked** when it waits for I/O.
- **Race condition** = the outcome depends on the timing of processes.
- **Thread** = **lightweight process**; threads of one process share the **address space and open files**.

### Scheduling and deadlocks
- **FCFS** = non-preemptive, arrival order. **SJF** = provably optimal **average waiting time** when all jobs arrive together.
- **Round Robin** gives each process a fixed **time quantum**.
- **Starvation** in priority scheduling is solved by **aging**.
- **Coffman conditions** (all four needed): mutual exclusion, hold and wait, **no preemption**, circular wait. ("Preemption" itself is not a condition.)
- **Banker's algorithm** = deadlock **avoidance**.

### Memory management
- **Paging**: virtual memory split into **pages**, physical memory into **page frames**. Virtual address = **page number + offset**.
- **TLB** = hardware cache of recent page-table entries.
- **Page fault** = referenced page is not in main memory.
- **Thrashing** = excessive paging; the CPU idles.
- **Best fit** = smallest hole that is big enough. **Internal fragmentation** = waste inside an allocated block.
- **Optimal** page replacement is the theoretical best but cannot be implemented.

### I/O and files
- **DMA** transfers data between device and memory without the CPU.
- **Block devices** (hard disk, SSD) vs character devices (keyboard, mouse). **RAID 1** = mirroring.
- **i-node** (UNIX) = file attributes + disk block addresses.
- Default file systems: **NTFS** (Windows), **ext4** (Linux), **APFS** (Apple Macs/iPhones).
- **/home** holds users' personal folders. `chmod 755` = **rwxr-xr-x**.

## What an OS does
- Software layer between hardware and user programs. Two roles: **extended machine / virtual machine** (hides hardware complexity through *system calls*) and **resource manager** (processor, memory, I/O, files; orderly, protected sharing).
- Resource sharing: **time multiplexing** (take turns, e.g., CPU/printer) and **space multiplexing** (each gets a part, e.g., memory/disk).
- Modes: **kernel (supervisor) mode** (OS, full hardware access) vs **user mode** (apps). A **trap** instruction switches user → kernel when making a **system call**.
- **Shell** = command interpreter (CLI/GUI) – *not* part of the kernel. **Kernel** = core. **System call** = interface to kernel (fork, exec, open, read, write, close, exit, wait).
- Main functions: process mgmt, memory mgmt, file mgmt, device (I/O) mgmt, security/protection, networking, user interface, accounting.
- **Booting:** power on → BIOS/UEFI POST → bootloader (GRUB, Windows Boot Manager) from **MBR/GPT** → kernel loads → init/systemd. MBR = sector 0, holds boot code + partition table (max 4 primary partitions, 2 TB). **GPT** supports > 2 TB, 128 partitions, used with UEFI.

## Types of operating systems
1. **Mainframe OS** – batch, transaction processing, timesharing (e.g., OS/390, z/OS).
2. **Server OS** – serve many users over a network (UNIX, Linux, Windows Server).
3. **Multiprocessor OS** – parallel/multicomputer/multiprocessor variants of server OS.
4. **Personal computer OS** – good interface for one user (Windows, macOS, Linux).
5. **Real-time OS (RTOS)** – meet deadlines. **Hard real-time**: missed deadline = catastrophe (industrial robots, pacemakers, airbags); **soft real-time**: occasional miss tolerated (audio/video). Examples: **VxWorks, QNX, FreeRTOS**.
6. **Embedded OS** – TVs, microwaves, phones; limited memory/power (PalmOS, Windows CE, Android Things).
7. **Smart-card OS** – smallest; some run a Java Virtual Machine/applets (JavaCard).
- Other classifications: **single-user single-tasking** (MS-DOS) vs **multitasking**; **batch**, **interactive/time-sharing**, **multiprogramming** (several jobs in memory to keep CPU busy), **multiprocessing** (multiple CPUs), **multithreading**, **distributed**, **mobile**.

## OS structures
| Structure | Idea | Example/notes |
|---|---|---|
| **Monolithic** | all OS procedures in one big program; any procedure can call any other; no information hiding; services via **trap** → table lookup by system-call number | classic UNIX, early Linux |
| **Layered** | hierarchy of layers, each uses only the one below | **THE system** (Dijkstra, Eindhoven, 1968; 6 layers: 0 processor allocation/multiprogramming → 1 memory/drum → 2 operator console communication → 3 I/O buffering → 4 user programs → 5 operator process) |
| **Virtual machine** | virtual machine monitor (hypervisor) runs on bare hardware, gives exact copies of hardware | **IBM VM/370 (CP/CMS)**; virtual 8086 mode; **JVM** (Sun's Java Virtual Machine) |
| **Exokernel** | gives each VM a *subset* of real resources (e.g., disk blocks 0–1023) → no remapping layer | MIT research |
| **Microkernel / client-server** | minimal kernel; most services (file, process, memory servers) run as user-mode processes; client sends message → server replies; a crashed server doesn't crash the OS; suits distributed systems | MINIX, QNX, Mach |
| **Hybrid** | mix of monolithic + microkernel | Windows NT, macOS (XNU) |
- **Hypervisors:** *Type 1* (bare-metal: VMware ESXi, Hyper-V, Xen, KVM) vs *Type 2* (hosted: VirtualBox, VMware Workstation). **Containers** (Docker, Kubernetes) share the host kernel – lighter than VMs.

## Processes
- **Process** = program in execution (code + data + stack + registers + PCB). Program = passive; process = active.
- **Pseudoparallelism:** single CPU switches rapidly among processes (multiprogramming). Each process gets illusion of own CPU (*virtual time*) and *virtual memory*.
- **Creation events:** system initialization, a running process calls a create system call (UNIX **fork**), user request, batch job initiation.
- **Termination:** normal exit (voluntary), error exit (voluntary), fatal error (involuntary), killed by another process (involuntary).
- **Hierarchy:** UNIX `fork()` creates a child (copy of parent); `exec()` replaces the program; `wait()` waits for children; tree rooted at **init** (PID 1). Windows has no hierarchy (handles).
- **Process states:** **New → Ready ↔ Running → Waiting/Blocked → Ready … → Terminated.**
  - Transitions: Ready→Running (scheduler dispatch); Running→Ready (time slice expired/preempted); Running→Blocked (waits for I/O/event); Blocked→Ready (I/O completes). (Coach's slide uses 3 states: running, blocked, ready.)
- **Process table / PCB** (process control block; PTE) – one entry per process: PID, state, program counter, registers, scheduling info, memory pointers, open files, accounting.
- **Context switch** = saving state of old process and loading new one (pure overhead).
- **Zombie** = terminated but not yet reaped by parent. **Orphan** = parent died (adopted by init). **Daemon** = background service.
- **IPC (inter-process communication):** pipes, message queues, shared memory, sockets, signals, semaphores.

## Threads
- **Thread** = unit of CPU execution within a process (“lightweight process”). Threads *share* address space, global data, open files, child processes; *each has its own* program counter, registers, stack, state.
- Reasons for threads: parallelism with blocking system calls (web server), faster to create/destroy than processes, natural for multicore, easy programming model. Solaris example: creation ~30× faster, context switch ~5× faster.
- Benefits: responsiveness, resource sharing, economy/speed, multiprocessor utilization.
- Drawbacks: **synchronization** (race conditions, deadlocks), lack of memory protection between threads.
- Models: user-level threads (kernel unaware; one blocks all), kernel-level threads, hybrid; mapping many-to-one, one-to-one, many-to-many. Examples: POSIX **pthreads**, Java `Thread`.
- **Race condition**: outcome depends on timing. **Critical section**: code accessing shared resource. Solutions: **mutex** (lock), **semaphore** (Dijkstra's P/V; counting vs binary), **monitor**, **spinlock**. Classic problems: producer–consumer, readers–writers, dining philosophers.

## CPU scheduling
- **Scheduler** picks next process; **dispatcher** gives it the CPU. Scheduling levels: long-term (job), medium-term (swap), short-term (CPU).
- **Criteria:** Fairness · **Throughput** (jobs/unit time) · **Turnaround time** (submission → completion) · **Waiting time** (time in ready queue) · **Response time** (submission → first response) · CPU utilization.
  - Turnaround = Completion − Arrival; Waiting = Turnaround − Burst.
- **CPU-bound** (long CPU bursts) vs **I/O-bound** (short CPU bursts).
- **Preemptive** (can interrupt) vs **non-preemptive** (runs until block/finish).
- **Environments:** Batch (non-preemptive OK), Interactive (preemptive necessary), Real-time.
- **Batch algorithms:**
  - **FCFS** – non-preemptive, FIFO queue; *convoy effect*; not optimal. Example P1=24, P2=3, P3=3 (arrive in order): avg waiting = (0+24+27)/3 = **17**; order P2,P3,P1 → (0+3+6)/3 = **3**.
  - **SJF (Shortest Job First)** – non-preemptive; **provably optimal avg waiting time when all jobs available at once**; needs run-time estimates; can starve long jobs. Example (coach's slide) A=5,B=2,C=4,D=1: FCFS order A,B,C,D → waits 0,5,7,11 → avg wait **5.75**; SJF order D,B,C,A → waits 0,1,3,7 → avg wait **2.75**.
    - ⚠️ The slide prints **8.75** and **5.75**, which are actually the average **turnaround** times (FCFS: 5,7,11,12 → 8.75; SJF: 1,3,7,12 → 5.75). Know both formulas and recompute on the exam.
  - Example: P1(arrive 0, burst 7), P2(2,4), P3(4,1), P4(5,5): **non-preemptive SJF** order P1,P3,P2,P4 → waits 0,3,6,7 → avg **4** ✓. **SRTN/preemptive** → P1(0–2), P2(2–4), P3(4–5), P2(5–7), P4(7–12), P1(12–17) → waits P1=10, P2=1, P3=0, P4=2 → avg **3.25** (the slide shows 3 with slightly inconsistent numbers—the idea is that preemptive SRTN < non-preemptive).
  - **SRTN / SRTF (Shortest Remaining Time Next/First)** – preemptive SJF.
- **Interactive algorithms:**
  - **Round Robin (RR)** – each process gets a **time quantum** (10–100 ms); no process waits more than (n−1)q; quantum too big → FCFS; too small → too many context switches. Example quantum 20, bursts P1=53,P2=17,P3=68,P4=24 → Gantt: P1 0–20, P2 20–37, P3 37–57, P4 57–77, P1 77–97, P3 97–117, P4 117–121, P1 121–134, P3 134–154, P3 154–162.
  - **Priority scheduling** – highest priority first (lower number = higher priority in many texts); can cause **starvation** → fix with **aging**. Example: P1(10,pri3), P2(1,pri1), P3(2,pri3), P4(1,pri4), P5(5,pri2) → order P2,P5,P1,P3,P4; avg wait = (6+0+16+18+1)/5 = **8.2**.
  - Others: Multilevel queue, Multilevel feedback queue, Lottery, Fair-share, **CFS** (Linux Completely Fair Scheduler), EDF/Rate-monotonic (real-time).

## Deadlocks
- **Deadlock** = a set of processes each waiting for an event that only another process in the set can cause.
- **Four necessary conditions (Coffman):** **Mutual exclusion · Hold and wait · No preemption · Circular wait.** (All four must hold.)
- **Resource-allocation graph:** circles = processes, squares = resources; cycle ⇒ deadlock (for single-instance resources).
- Strategies: **Ostrich algorithm** (ignore), **Detection & recovery** (kill process/rollback/preempt), **Avoidance** (**Banker's Algorithm**—Dijkstra; safe state), **Prevention** (break one of the four conditions, e.g., impose resource ordering to break circular wait).
- **Starvation** (indefinite postponement) ≠ deadlock. **Livelock** = processes keep changing state but make no progress.

## Memory management
- **Memory manager** tracks used/free memory, allocates/deallocates, handles swapping between RAM and disk.
- **Monoprogramming** (one program + OS), **multiprogramming with fixed partitions** (N partitions; single input queue better; poor utilization → *internal fragmentation*), **variable partitions** (→ *external fragmentation*, fix by **compaction**).
- **Relocation & protection** problems → **base and limit registers** (base added to every address; limit = partition length). IBM 360 used 4-bit protection key in PSW.
- **Swapping**: moving whole processes between RAM and disk.
- **Tracking free memory:** **Bitmap** (1 bit per allocation unit: 0 free, 1 used) vs **Linked list** of segments (P/H entries).
- **Allocation algorithms:** **First fit** (first hole big enough, fast) · **Next fit** (continue from last position) · **Best fit** (smallest adequate hole; slower, leaves tiny holes) · **Worst fit** (largest hole) · **Quick fit** (separate lists for common sizes).
- **Overlays**: programmer splits program into pieces swapped in/out → replaced by **virtual memory**.
- **Paging:**
  - Virtual address space split into **pages**; physical memory into **page frames** (same size). **MMU** maps virtual → physical.
  - Virtual address = **page number + offset**. **Page table** entry gives frame number (+ present/absent, protection, modified/dirty, referenced bits).
  - **Page fault** = referenced page not in memory → trap → OS loads page from disk (may evict another).
  - **TLB** (Translation Lookaside Buffer, “associative memory”) caches recent page-table entries inside MMU. **Multilevel page tables** reduce table size.
  - Example: 4 KB pages; virtual address 8196 → page 2 offset 4. With 16 pages of 4 KB in virtual space, address = 16 bits (4-bit page number + 12-bit offset).
  - **Page replacement algorithms:** **Optimal** (theoretical best), **FIFO** (may show **Belady's anomaly**), **LRU** (least recently used), **Clock/Second chance**, **NRU**, **LFU**. **Thrashing** = excessive paging, CPU idles.
- **Segmentation:** multiple independent address spaces (segments) of varying length (code, data, stack); address = (segment number, offset); good for sharing/protection; causes **external fragmentation (“checkerboarding”)** → compaction. Combined **segmented paging** (Intel x86 historically).
- **Fragmentation:** internal (wasted inside allocated block — fixed partitions/paging last page) vs external (scattered free holes — segmentation/variable partitions).
- **Virtual memory** lets programs exceed physical RAM; **swap space/pagefile**.

## I/O and device management · finals
- **Block devices** (fixed-size addressable blocks: HDD, SSD, CD-ROM, USB) vs **character devices** (stream: keyboard, mouse, printer, NIC).
- **Device controller** = electronic part (has registers + buffer); **device driver** = OS software for that controller.
- **Talking to devices (3 approaches):** special I/O instructions with **I/O ports**; **memory-mapped I/O**; **DMA**.
- **DMA (Direct Memory Access):** DMA controller transfers data between device and memory without CPU; steps: CPU programs DMA → DMA requests read from disk controller → data written to memory → ack → counter updated → **interrupt** when done. Modes: **cycle stealing** (word-at-a-time), **burst mode** (block), **fly-by**.
- **Interrupts:** device signals completion via interrupt controller → CPU runs **interrupt handler (ISR)**. Types: hardware vs software (traps/exceptions).
- **Ways to perform I/O:** **Programmed I/O (polling/busy waiting)**, **Interrupt-driven I/O**, **DMA**.
- **Buffering** reasons: speed mismatch, different transfer sizes, copy semantics. Strategies: **single/double buffering**, **circular buffer**. **Spooling** = queue output to disk for a dedicated device (printer).
- **Dedicated devices** (printer/tape) allocated to one process at a time.
- **Disk geometry:** platters → surfaces → **tracks** → **sectors** (gaps between); same track on all surfaces = **cylinder**. Access time = **seek time + rotational latency + transfer time**.
- **Disk scheduling:** **FCFS, SSTF** (shortest seek time first), **SCAN / elevator**, **C-SCAN**, **LOOK**.
- **RAID levels:** 0 (striping, no redundancy), 1 (mirroring), 5 (striping + distributed parity, ≥3 disks), 6 (double parity), 10 (1+0).
- **Optical disks:** CD-ROM (read-only), CD-R (write once), CD-RW (rewritable); DVD 4.7 GB–17 GB (tighter pits, second layer, two-sided); data stored as **pits and lands** (laser reflection; transition = 1, no change = 0).
- **Bad sectors:** handled by controller (spare sector substitution or shifting) or OS (remapping table).
- **Stable storage:** pair of identical disks; **stable write** (write block on drive 1, verify, retry n times, remap), **stable read** (read drive 1, retry, then drive 2), **crash recovery** (compare both drives and repair).

## File systems
- Requirements: store very large info; survive process termination (persistent); concurrent access.
- **File naming:** extension indicates type; UNIX is case-sensitive, MS-DOS isn't; 8.3 names (DOS) vs 255 chars.
- **File structure:** byte sequence (UNIX/Windows), record sequence (fixed-length), tree of records (key field; mainframes).
- **File types:** regular (ASCII or binary), directories, **character special files**, **block special files** (UNIX).
- **Access:** **sequential** vs **random access** (seek).
- **Attributes:** name, size, owner, permissions, timestamps (created/modified/accessed), hidden, archive.
- **Operations:** create, delete, open, close, read, write, append, seek, get/set attributes, rename. **Directory ops:** create, delete, opendir, closedir, readdir, rename, link, unlink.
- **Memory-mapped files** via map/unmap system calls.
- **Directory systems:** single-level (all files in root; name clashes) → two-level (one directory per user) → **hierarchical (tree)**.
- **Paths:** **absolute** (from root; `/usr/ast/mailbox`, `C:\Users\...`) vs **relative** (from working directory); `.` = current, `..` = parent.
- **Layout:** sector 0 = **MBR** (+ partition table) → active partition's **boot block** → **superblock** (FS type, number of blocks, params) → free-space management → **i-nodes** → root directory → files/dirs.
- **Implementing files:** **contiguous allocation** (fast reads; external fragmentation), **linked list allocation**, **linked list with table in memory = FAT (File Allocation Table)**, **i-node** (index node listing attributes + disk block addresses).
- **File systems list:** FAT12/16/**FAT32** (4 GB file limit), **exFAT**, **NTFS** (Windows: journaling, permissions, compression, encryption/EFS, large files), **ext4** (Linux), **APFS** (Apple), HFS+, **ZFS**, **Btrfs**, ReFS, ISO 9660 (CD), UDF.
- **Backups:** to recover from disaster and from "stupidity"; **full, incremental, differential**; **physical dump** (block 0 to end) vs **logical dump** (directories/files changed since base date). **3-2-1 rule**: 3 copies, 2 media, 1 offsite.
- **UNIX permissions:** rwx for user/group/others; `chmod 755` = rwxr-xr-x; r=4,w=2,x=1.
